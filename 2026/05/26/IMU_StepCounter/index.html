IMU的计步算法设计

写于：2026-05-26

代码已开源，点击这里查看

摘要

本研究设计了一套基于 IMU 的低功耗计步算法。算法采用“先分类，后计步”的两阶段流程，首先融合加速度与陀螺仪特征，利用随机森林与隐马尔可夫模型（HMM）精准识别步行、跑步与干扰动作，分类准确率 100%；随后根据运动模式，采用差异化参数的带通滤波与自适应峰值检测进行计步。

针对核心挑战，算法进行了两项关键优化：

  1. 引入自相关分析动态确定峰间距，解决跑步时可能因手臂摆动导致的“一步双峰”超计问题。
  2. 采用基于能量包络的活跃区域过滤，有效抑制起止阶段的低能量伪峰干扰。

在包含 80 个文件的测试中，算法实现了平均绝对误差（MAE）0.88 步，平均绝对百分比误差（MAPE）7.34%。通过上述优化，跑步模式的计数误差显著降低，三种状态下的计步均在可控范围之内。算法复杂度低，满足嵌入式实时处理要求，为资源受限的可穿戴设备提供了有效的步数统计解决方案。

关键词：计步算法、运动状态识别、自适应峰值检测、随机森林分类

1. 项目背景与目标

1.1 任务描述

针对佩戴的 6 轴 IMU 设备，利用采集到的数据集，设计一套低功耗、高精度的计步算法。任务的核心目标是精准识别步行和跑步状态，剔除噪声干扰，实现步数的精准统计。

1.2 数据集描述

  • 数据集基于真实开发板采集，包含走路、跑步及其他干扰动作。文件名已标注真实步行次数。
  • 在 AccData 文件夹中，包含三个动作标签：“走路”对应 walk 子文件夹，“跑步”对应 run 子文件夹，“其他”对应 others 子文件夹。
  • TXT 文件名示例：IMU_run_left_2026_04_28_16_05_05_ID3_step30.txt
    • run 为数据状态标签。
    • ID3 为佩戴者序列号。
    • step30 表示真实计步数为 30 步。
  • TXT 文件内部格式说明：
    • 前 5 行为数据头，标注设备、采集时间、采样率、数据精度、数据轴数。
    • 之后为 IMU 数据，7 个为一组，依次为：X/Y/Z 轴陀螺仪、X/Y/Z 轴加速度计、调试数据（不使用）。
  • 数据分布：共 80 个 TXT 文件，其中 run 12 个、walk 12 个、others 56 个。
  • others 状态标签的真实步数为 0，包含切菜、刷牙、挥手、健身等干扰动作，需要在算法中剔除误计步。

1.3 评估指标定义

以下为官方要求的关键指标：

  1. MAE（平均绝对误差）
    $$
    \mathrm{MAE} = \frac{1}{N} \sum_{i=1}^{N} |\mathrm{Pred}_i - \mathrm{True}_i|
    $$
  2. MAPE（平均绝对百分比误差，仅对 walk+run 计算）
    $$
    \mathrm{MAPE} = \frac{1}{N_{walk+run}} \sum_{i=1}^{N_{walk+run}} \frac{|\mathrm{Pred}_i - \mathrm{True}_i|}{\mathrm{True}_i} \times 100%
    $$
  3. 分类准确率：运动状态识别的准确率。

2. 算法架构设计

2.1 整体流程

本算法采用“先分类，后计步”的两阶段策略，将运动识别与步数统计两个任务划分。执行流程如下：

  1. 数据加载与解析：读取 TXT 文件，解析头部信息与原始数据流，提取六轴数据并进行物理单位转换。
  2. 数据集划分：原始数据集按 8:2 划分训练集与测试集，并随机分配三种标签，保证比例一致。
  3. 阶段一：运动状态识别。利用滑动窗口提取时域与频域特征，通过平衡随机森林分类器进行初步判别，再结合 HMM 进行时序平滑，输出稳定标签（walk/run/others）。
  4. 阶段二：自适应峰值计步。若识别为 walk 或 run，则对原始加速度幅值信号进行带通滤波与峰值检测；若为 others，则直接输出 0 步。

2.2 关键设计决策

模块 决策方案 设计理由
信号源选择 计步使用原始加速度幅值 避免滑动平均平滑掉脚步冲击尖峰，保留原始尖峰信息
分类器 随机森林（100 trees） 数据集较小且需嵌入式部署，优先轻量模型
时序处理 HMM + 置信度阈值 消除逐帧分类抖动，防止低置信度误判
峰值检测 检测正峰（Positive Peaks） 带通后信号过零，直接检测正峰避免整流导致频率翻倍

3. 算法的具体实现

3.1 阶段一：运动状态识别

本阶段为运动状态识别模块设计，用于判断佩戴用户当前处于 walk、run 还是 others 状态，是后续计步的前提。

3.1.1 特征工程

根据 preprocess 函数逻辑，设计了差异化信号处理路径。本文采用滑动窗口法，窗口长度 128 样本（2.56 秒），步长 64 样本（50% 重叠），提取 7 维特征向量：

  1. 时域特征：加速度幅值标准差（acc_std）、均值（acc_mean）、范围（acc_range）以及陀螺仪幅值标准差（gyro_std）。
  2. 组合特征：加速度与陀螺仪标准差比值（acc_gyro_ratio）。
  3. 频域特征：FFT 提取主频（dominant_freq）及步频频段（0.8~5.0 Hz）能量占比（spectral_ratio）。

3.1.2 分类与平滑

本文选择平衡随机森林：100 棵树、最大深度 10，并通过 min_samples_leaf=5 防止过拟合。同时使用 HMM 时序平滑，基于 Viterbi 算法解码，利用高自转移概率约束输出，消除毫秒级频繁切换抖动。

3.2 阶段二：自适应峰值计步

3.2.1 信号处理流程

  1. 幅值合成：直接使用三轴原始加速度合成幅值，保留冲击信号尖锐特性。
    $$
    acc_mag = \sqrt{a_x^2 + a_y^2 + a_z^2}
    $$
  2. 带通滤波：根据阶段一识别结果动态选择滤波参数。walk 模式（0.53.0 Hz）保留低频步态，run 模式（1.55.5 Hz）抑制低频晃动。
  3. 峰值检测：采用 find_peaks 算法，基于信号标准差设置高度阈值，并设置最小峰间距。
  4. 自相关引导：针对跑步时手臂摆动导致的“一步双峰”超计问题，引入自相关函数检测信号基频周期，以此动态调整最小峰间距。
  5. 活跃区域过滤：计算信号包络的滑动 RMS，剔除起止阶段低能量伪峰，提高计数纯净度。

3.2.2 差异化参数

参数 walk run 说明
带通低频 0.5 Hz 1.5 Hz 步频下限 + 余量
带通高频 3.0 Hz 5.5 Hz 步频上限 + 余量
默认最小峰间距 0.38 秒 0.25 秒 防止一步双计
阈值系数 0.25 × std 0.20 × std walk 阈值高，抑制噪声
突出度系数 0.6 0.8 run 要求更高峰突出度
正则范围 0.5~2.0 × 中位 0.5~2.0 × 中位 统一约束范围

3.3 技术说明

在步频检测算法的设计与优化过程中，几个关键决策显著提升了计数准确性。

首先，算法刻意避免对带通滤波后的信号进行全波整流（abs）操作。滤波后信号围绕零值线振荡，单一步伐会同时产生一个正峰与一个负谷，整流会将其合并为两个峰，导致基频翻倍并产生超计。因此算法直接检测正峰，确保“一步一峰”。

其次，算法直接使用原始加速度模值信号，而非滑动平均或去重力后的信号。预处理会削弱脚步落地时的尖锐冲击峰，导致系统性欠计，原始信号能更好保留关键时域特征。

此外，算法引入自相关引导的动态最小峰间距设置，专门针对跑步模式。腕部传感器在跑步时可能出现单步双峰，固定间距会造成系统性超计。为此对滤波后信号计算自相关函数，在步频频段内寻找主峰获得基频周期 T，并用 T 替代固定 min_distance 参数。保护条件为：新周期检测到的峰数量不低于默认结果的 80%，且隐含步频不低于 1.5 Hz，才采纳该结果。

最后，采用基于能量包络的活跃区域过滤。通过 1 秒窗口滑动 RMS 获取信号包络，阈值设为整体 RMS 的 0.4 倍，仅保留高能量“活跃区域”内峰值。若过滤后活跃区域持续时间不足总时长的 30%，则自动降阈值至整体 RMS 的 0.25 倍，避免低强度运动中过度过滤有效步伐。

4. 测试结果与分析

4.1 总体性能指标

遍历 AccData 文件下的 80 个 IMU 数据，统计最终 MAE 与 MAPE 如下：

指标 误差
MAE 0.88 步
MAPE 7.34%
分类准确率（文件分类） 100%

下图展示了最终计步算法的评估结果，主要从预测步数与真实步数的拟合关系、误差分布、不同运动类别下的误差情况等方面分析。整体来看，算法在 80 组测试样本上的表现较好，平均绝对误差 MAE 为 0.88 步，均方根误差 RMSE 为 2.05 步，平均绝对百分比误差 MAPE 为 7.34%。

从“预测 vs 真实步数”散点图可以看出，大部分样本点分布在理想线附近，说明算法输出整体接近真实步数。对于 walk、run 和 others 三类数据，预测结果均能较好反映真实步数变化趋势。其中 others 类别真实步数与预测步数基本为 0，说明算法能较准确地区分非步行动作。

从误差分布直方图可以看出，误差主要集中在 0 附近，少量样本存在正负偏差。整体误差分布较集中，说明算法稳定性较好，但个别样本仍存在低估或高估现象。

各类别绝对误差箱线图进一步展示了不同运动类别下的误差差异。walk 类别的绝对误差范围较宽，最大误差接近 9 步；run 类别误差更集中，整体误差小于 walk；others 类别误差几乎为 0。统计结果显示，walk 类别 MAE 为 3.67 步、MAPE 为 9.14%；run 类别 MAE 为 2.17 步、MAPE 为 5.54%，表明跑步场景的计步精度略优于步行场景。

4.2 性能分析

基于 IMU 步频检测算法的测试与分析，本研究的性能表现、系统特性及改进方向如下。

算法已成功解决跑步模式下的系统性超计问题。通过可视化结果，针对性选取 run_step60 文件分析，发现由于手臂摆动等原因，每步产生两个振荡峰，造成 14 步的超计误差。引入自相关引导最小峰间距后，有效过滤多余峰，将该文件误差降为 0。

步行模式仍面临两类挑战：一是弱信号文件（如 walk_step40），加速度变化过小导致部分步伐未形成可检测峰值，造成欠计；二是短时程文件（如 walk_step20），低信噪比与手臂摆动引入额外峰分量导致超计。这揭示了在极端信号条件下算法的固有限制。

时间复杂度方面，特征提取、随机森林分类及峰值检测均为线性或近似线性复杂度。空间复杂度方面，系统运行时内存占用约 4 KB，包含数据缓冲、特征向量、模型及 HMM 参数。在 20 ms 采样周期下，单次处理时间小于 5 ms，为流式处理留出约 75% 时间裕量，证明工程可行性。

在测试集上取得 7.34% 的 MAPE。相比 Apple Watch 等产品依赖多传感器融合、海量训练数据及个性化校准，可将误差控制在 1%~5%，这说明单传感器与小规模数据在精度上存在上限。

改进建议：

  1. 算法层面：探索多尺度峰值检测以应对弱信号，并研究结合陀螺仪的轻量融合策略。
  2. 数据层面：扩大训练集规模，覆盖更多弱信号、变速运动及不同佩戴位置数据。
  3. 系统层面：若条件允许，佩戴于腰部可获取更接近身体质心的强步态信号。

5. 提交文件说明

  1. step_counter.py：两阶段计步主算法仿真文件。

    • 输入：单文件路径；首次运行自动训练并缓存模型。

    • 运行：python step_counter.py [imu_file_path]

    • 输出：真实步数与预测步数、误差、预测类别、真实类别、模型参数文件 .pkl。

  1. export_c_header.py：将已训练模型导出为 C 头文件。

    • 运行（在 Python 仿真目录）：python export_c_header.py
    • 说明：读取 Python 仿真/model_output 下的模型文件并生成 C 版本参数，同步到 C 代码目录。

  2. evaluate_all.py：批量评估脚本，遍历 walk/run/others，统计 MAE/MAPE/RMSE 并生成图表与 CSV。

    • 运行（在 Python 仿真目录）：python evaluate_all.py
  • 输出：Evaluation_output 目录。

  1. step_counter.c：C 语言计步实现，内置 main 可单文件测试，依赖 step_counter_model.h。

    • 编译（在 C 代码目录）：gcc step_counter.c -o step_counter.exe -lm

    • 运行：.\step_counter.exe <imu_file_path>

6. 结论

在 80 个文件的手腕 IMU 数据集上，本文所设计的“先分类，后计步”两阶段算法实现了优异的综合性能，平均绝对误差为 0.88 步，平均绝对百分比误差为 7.34%，分类准确率达到 100%。通过引入自相关引导最小峰间距和基于能量包络的活跃区域过滤，有效解决跑步时“一步双峰”系统性超计问题，使跑步模式的 MAE 和 MAPE 分别显著降低 26% 和 20%。

算法在步行模式下对个别弱信号或短时程文件的处理仍存在误差，这揭示了在极端信噪比条件下基于单加速度传感器方案的局限。整体上，本算法在有限数据集与计算资源约束下达成了性能与效率的良好平衡。后续工作将集中于扩充训练数据、覆盖更多运动场景，并探索融合陀螺仪信息等轻量级传感器融合策略，以进一步提升算法在复杂真实环境中的鲁棒性与普适性。
