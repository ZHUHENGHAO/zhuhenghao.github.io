AUTOSAR 的概念理解

写于：2026-06-24

摘要

​ 在 VCUPlus（基于英飞凌 TC397 的整车控制器）项目里接触 AUTOSAR 后，把这块知识做了精简梳理。这篇文章主要梳理：AUTOSAR 的核心概念（分层架构、SWC/RTE/BSW、文件格式、接口类型），以及从零创建一个 AUTOSAR 功能的完整步骤。所有路径、模块名均落地到 VCUPlus 项目真实结构，便于复盘。

第一章：AUTOSAR 核心概念

1. AUTOSAR 是什么、为什么要分层

传统裸机开发直接操作寄存器，在汽车电子里有三个致命问题：换芯片代码全作废、软件无法跨项目复用、无法满足 ISO 26262 功能安全。

AUTOSAR（AUTomotive Open System ARchitecture） 是全球标准化的汽车软件架构，核心思想是分层 + 标准化接口：每层只通过定义好的接口与上下层通信，换芯片只需换最底层驱动，应用层一行不用改。AUTOSAR 交付的是规范（方法论 + 元模型 + ARXML 格式），厂商据此实现工具链（Vector DaVinci、ETAS ISOLAR、EB tresos）。

2. 三层软件架构

层级 全称 职责 代码来源
应用层 ASW Application Layer 整车业务逻辑，与硬件完全解耦 框架工具生成 + 逻辑手写
RTE Runtime Environment 应用与底层的通信枢纽，实现软硬解耦 100% 工具生成，禁止手改
BSW Basic Software OS / 通信 / 诊断 / 存储等基础服务 + 硬件驱动 工具配置生成

RTE 是关键：应用层调 Rte_Read/Write/Call 时，完全不知道数据来自 CAN 还是另一个 SWC。它是一堆”胶水代码”，把标准化的 SWC 接口和 BSW 能力一一映射。

3. BSW 的四层细分

  • MCAL 由芯片厂提供（如英飞凌 MC-ISAR 包），经 ASIL 功能安全预认证，必须工具生成不可手写。
  • CDD 是逃生口：标准栈覆盖不了的硬实时外设走旁路直接访问硬件。

4. 核心术语速查

概念 全称 大白话
SWC Software Component 功能黑盒子，含多个 Runnable，通过 Port 对外通信
Runnable Runnable Entity SWC 内可被 OS 调度的执行函数（周期/事件触发）
Port / Interface Port SWC 的对外插头；接口分 S/R、C/S 两类
RTE Runtime Environment 连接 SWC↔SWC、SWC↔BSW 的通信管道
VFB Virtual Function Bus 所有 SWC 通信的逻辑总线，RTE 是其在 ECU 上的实现

两种接口类型：

  • S/R（Sender/Receiver）：广播式数据流，Rte_Read_* / Rte_Write_*，用于信号、状态值。
  • C/S（Client/Server）：请求-应答式服务，Rte_Call_*，用于”读时间””请求关机”等操作。

5. 文件格式速查

AUTOSAR 项目文件分三类：设计图纸（给工具看）、工程源码（参与编译）、固件产物。

格式 全称 本质 作用
.arxml AUTOSAR XML 设计图纸 SWC 接口、BSW 描述、系统信息，所有工具的唯一语言
.dpa DaVinci Project Archive BSW 工程入口 记录引用的 ARXML、模块、输出路径
.dvp/.dvg DaVinci Project/Group SWC 设计 组件类型定义，Developer 私有格式
.c/.h（生成） — 工程源码 RTE 接口、BSW 配置，禁止手改
.c/.h（手写） — 工程源码 Runnable 业务逻辑，工程师自由编写
.hex/.s19 Intel HEX / S-Record 固件产物 产线刷写（带地址信息）
.out GHS Executable 固件产物 带调试信息，Lauterbach 加载
.gbf GM Boot Format 固件产物 GM 产线专用签名固件

6. Classic vs Adaptive

维度 Classic (CP) Adaptive (AP)
定位 深度嵌入式、实时控制 高性能计算、座舱/智驾
系统 AUTOSAR OS POSIX（基于 Linux）
通信 CAN/LIN/FlexRay 以太网 SOME/IP、DDS
调度 静态、确定性强 动态、面向服务

VCUPlus 的 TC397 跑 Classic；座舱 SoC 跑 Adaptive，两者经以太网交互。

第二章：创建 AUTOSAR 项目的全流程

开发链路总览

AUTOSAR 的代码大部分是工具根据配置自动生成的，所以必须”先画图纸再填砖块”：

为什么不能先写代码再配置？ RTE 代码由 SWC 接口（ARXML）自动生成。不定接口，工具不知道要生成什么样的 Rte_Read/Write，应用层也编不过。

阶段一：系统架构与 SWC 设计

工具：DaVinci Developer。输入：需求文档、通信矩阵。输出：.dvg（私有格式）+ SWC 接口 ARXML。

  1. 新建 SWC 组件类型（如 SWC_INFO_RTC）。
  2. 定义端口与接口（契约优先）：
    • S/R 接收 RTC_Data_CANSigR（从 CAN 收 RTC 同步数据）
    • S/R 发送 LocalDateTimeP（向其他 SWC 发布本地时间）
    • C/S 客户端 RTC_Get_Date_TimeC（调用下层 SWC 获取硬件时间）
  3. 定义 Runnable 与触发方式：RTC_DateTime_Run（TimingEvent 周期触发）、RTC_LocalDateTime_onCAN（DataReceivedEvent）。
  4. File → Export → AUTOSAR XML 导出标准 ARXML。

阶段二：应用层 SWC 业务逻辑开发

铁律：应用层绝不直接操作硬件、不直接调 BSW 函数，所有数据交换走 Rte_Read/Write/Call。

阶段三：BSW 底层模块配置

工具：DaVinci Configurator Classic。Developer 画 SWC 积木，Configurator 搭地基（配 OS、Com、Dcm 等参数）。

  1. 导入系统 ARXML，加载 .dpa 工程（conv-mvp.dpa）。
  2. 配置 MCAL：Can_17_McmCan（波特率/邮箱）、Adc、Dio、Gpt、Fls。
  3. 配置 BSW 服务模块：Com（信号路由到 Rte_Read_RTC_Data_CANSig）、Os（建 Task）、EcuM（启动序列）。
  4. Runnable ↔ Task 映射（关键）：把 RTC_DateTime_Run 挂到 Task_10ms，RTC_LocalDateTime_onCAN 设为事件触发。
  5. 校验并生成 → BSW C 代码输出到 GenData/。

阶段四：RTE 生成与对接

工具：DVCfgCmd.exe（Configurator 命令行版）。输入：.dpa + 全部 ARXML。输出：Rte.c、Rte_SWC_*.h、调度代码到 GenData/。

  • RTE 代码 100% 工具生成，禁止手改。
  • 完整数据流：CAN → MCAL → CanIf → Com → RTE → Rte_Read_* → SWC 业务 → Rte_Write_* → RTE 路由转发。
  • 增量加速：只改业务逻辑用 --rte NOGEN 跳过生成器（省 10-20 分钟）；改了 ARXML 才需 --rte GEN。

阶段五：代码整合与工程适配

文件 放置目录
SWC 业务源码 Autosar/Application/GM/gmGemIPCSwc/ImpArch/SWC_*_SRC/
SWC ARXML 同目录 arxml/
RTE 头文件 同目录 inc/
BSW 生成代码 Vector_bsw_cfg/GM/VCUPLUS_TC39x/GenData/
SWC CMake 每个 SWC 目录自己的 CMakeLists.txt

新增普通业务 SWC 一般不需要改链接脚本，顶层 CMake 自动扫描 ImpArch/。

第三章：构建链路速记

VCUPlus 构建经六层：入口脚本（Action1_Build.py）→ CMake → Ninja → Green Hills 编译（cctri）→ 链接（cxtri + .ld）→ 后处理（签名 .gbf）。

关键构建参数：

参数 可选值 作用
-o BM/BL/BLU/APP/HSM 选择构建分区
-t DEBUG/USER/PROD 编译类型（优化等级、调试信息）
-tc TC377T/TC387Q/TC397X 目标芯片
-r GEN/NOGEN 是否重新生成 RTE

第四章：要点速记

  • 描述优先：先定 SWC 接口（ARXML）再动 BSW，ARXML 是唯一真源。
  • RTE 是隔离带：应用层永远不碰寄存器，否则解耦失效。
  • 换 MCU 只重配 MCAL：上层 BSW 基本不动——这就是 AUTOSAR 的复用价值。
  • 生成代码不可手改：RTE、BSW 配置代码改了就被重新生成覆盖；要改改配置再 Generate。
  • CDD 是逃生口：标准栈搞不定的硬实时走旁路，但需在文档标注。
  • 工具链兼容有坑：各家 ARXML 不完全兼容，跨工具迁移务必先 Validate。
